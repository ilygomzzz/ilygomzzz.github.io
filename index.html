Tag-Me Banco + tienda · en equipo

GitHub ↗

Dos backends Spring Boot que se hablan por HTTP: una tienda online que cobra con tarjeta contra una API bancaria propia, con sus frontends en Angular. Mi parte fue sobre todo el backend.

Java 21Spring BootJPAAngularMariaDBFlywayTestcontainersJWT

Reto

Cada backend en capas con el dominio en el centro, la persistencia y el cliente HTTP detrás de interfaces, y poder probar el pago sin el banco real.

Solución

  • Banco: controller · usecase · domain · persistence, con casos de uso para pago con tarjeta y transferencia, JWT y validación de IBAN.
  • Tienda: controller · domain · persistence y un módulo integration (cliente HTTP y pago contra el banco); sesiones con token Bearer en base de datos.
  • En ambos: repositorios como interfaces del dominio, contraseñas con hash (password4j) y Bean Validation.
  • Flyway, tests de DAOs con Testcontainers (MariaDB) y el pago de la tienda probado con mocks.

Agentes en la práctica

Aules Digest Orquestación de agentes · SDD · código privado

Mi banco de pruebas para trabajar con agentes de forma ordenada: lee la API de Moodle, me resume el curso en el móvil, monta el entorno de cada tarea y genera apuntes con tarjetas Anki. Funciona solo, con un temporizador de systemd.

  1. Spec primero

    Cada pieza nace en un specs/NN-*.md con visión, no-objetivos y criterio de éxito. Cada tarea lleva un BRIEF.md y un ACCEPTANCE.md con checklist verificable.

  2. Orquesto

    Una skill coordina agentes pequeños de un solo cometido (descargar, crear repo, montar entorno, redactar apuntes), cada uno con las herramientas mínimas y el modelo más barato que le sirve.

  3. Valido

    Primero comprobaciones deterministas en Python (autor de git, secretos, tamaños, checklist completo). Después un agente validador independiente contrasta el brief con el material. Hasta 3 rondas.

  4. Publico

    Con el PASS, otro agente abre la pull request y me manda el enlace al móvil. Las tareas con fecha acaban en Google Calendar, un calendario por asignatura.

Personalization Dotfiles · Hyprland · Quickshell

Toda la configuración de mi Arch como repositorio reproducible, y el sitio donde afino cómo trabajo con Claude Code.

Qué hay

  • Dotfiles con instalador y symlinks para clonar el PC entero.
  • Gadgets propios en Quickshell/QML: calendario y tiempo de escritorio, barra superior y cristal con shaders GLSL.
  • Google Calendar como hub entre PC e iPhone, con un CLI propio de OAuth y sincronización.

Cómo lo organizo

  • Un CLAUDE.md como fuente de verdad: cada cambio es una fila en la tabla, conocimiento en una skill y una nota en el vault.
  • Skills por dominio (Hyprland, noctalia, diseño Quickshell) que se cargan según la tarea.
  • Nada está hecho hasta verificarlo en la sesión viva con una captura.
  • Un vault de Obsidian enlaza todos mis proyectos y sirve de memoria navegable.
